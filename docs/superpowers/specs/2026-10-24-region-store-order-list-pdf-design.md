# Region Store Order List PDF Design

## Goal

Replace the current sequential daily order-list PDF with a landscape dispatch sheet that groups pending orders by region and then by store, following the supplied Wonderful Moment reference layout.

## Scope

`Send now` and scheduled daily sends use the same renderer. No storefront, order creation, database migration, or Telegram API behaviour changes are required.

## Layout

- Render A4 landscape pages.
- The first page header shows the organization name, business date, generated Malaysia time, and total pending-order count.
- Render one region at a time. Each region starts on a new page with a clear region heading.
- Within a region, lay out store cards in a fixed four-column grid, mirroring the reference document's multiple adjacent store panels.
- Each store card uses a dark header row with `Name`, `Packet`, and `Add-Ons`, and a dark vertical side label containing the store name.
- `Name` is the customer name. `Packet` is the sum of all item quantities in an order. `Add-Ons` contains a readable comma-separated product list and any customer remark.
- Store cards reserve a stable number of rows. When a store exceeds the card capacity, its continuation uses another card labelled with the same store. When the current page has no remaining card slot, begin a new page with the region heading repeated.
- Orders with no assigned store are included under a `General` store card so no pending order is omitted.

## Data Flow

1. The notification service fetches pending orders for the active tenant with the associated branch and region names.
2. It fetches their order items, attaches items to each order, and sends rows to the PDF renderer.
3. The renderer groups rows as `region -> store`, preserving oldest-first order within each store.
4. The generated PDF is sent through the existing Telegram `sendDocument` flow and notification jobs are marked sent exactly as today.

## Error Handling

- A missing branch or region must not fail dispatch: orders go into `General` or `Unassigned region` respectively.
- Empty item lists render an em dash in the Add-Ons cell and contribute zero to Packet.
- Text is truncated to each cell's available width rather than overflowing into neighbouring cards.

## Verification

- Unit tests assert the formatting helpers and grouping rules include every row, keep stores isolated, and handle unassigned orders.
- Renderer tests load the generated bytes with `pdf-lib`, verify a landscape page is produced, and confirm it grows to additional pages for more store cards than fit on one page.
- Existing dashboard tests continue to verify that `Send now` sends a PDF and marks pending notification jobs as sent.
